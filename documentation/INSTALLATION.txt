╚════════════════════════════════════════════════════════════════════════════╝

Karaoke Studio Pro v3 supports two supported launch paths:

1. Run directly from source during development
2. Launch a packaged build for end-user distribution

The current packaged Windows output is:
  build_system\dist\KaraokeStudioPro\KaraokeStudioProV3.exe

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 SYSTEM REQUIREMENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✓ Windows 10/11 recommended (Windows 7 SP1+ may still work, but 10/11 is the verified target)
✓ Python 3.10+ for source runs; Python 3.13 is the verified packaging runtime
✓ 500 MB free disk space for the build and bundled media tools
✓ For packaged builds: FFmpeg, FFprobe, yt-dlp, and VLC runtime files are bundled in the distribution
✓ For source runs: install the project requirements before launching the app

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 SOURCE SETUP
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Open PowerShell in the project root
   cd D:\Srikanth\Academics\Python\karaoke-player

2. Install runtime dependencies
   python -m pip install -r documentation\requirements.txt

3. Launch the app from source
   python .\source_code\main.py

Note:
- The app automatically resolves VLC runtime files from `resources\libvlc.dll` and `resources\plugins\` when present.
- No manual VLC PATH export is required for a normal source run.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 PACKAGED BUILD SETUP
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Install the build toolchain
   python -m pip install -r build_system\requirements-build.txt

2. Build the standalone package
   python build_system\build.py

3. Locate the packaged executable
   build_system\dist\KaraokeStudioPro\KaraokeStudioProV3.exe

4. Distribute the whole folder or ZIP archive to end users
   - Folder: `build_system\dist\KaraokeStudioPro\`
   - ZIP: `build_system\dist\KaraokeStudioPro_v3_*.zip`

The packaged build includes the required FFmpeg, FFprobe, yt-dlp, VLC runtime DLLs, the VLC plugins directory, splash assets, and the offline Demucs model cache.

 CONFIGURATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Use the Settings dialog to configure:
├─ FFmpeg Path          - FFmpeg binary location (usually auto-detected)
├─ FFprobe Path         - FFprobe binary location (usually auto-detected)
├─ yt-dlp Path          - yt-dlp executable location (usually auto-detected)
├─ Download Directory   - Where downloads are saved
├─ Measurement Mode     - dBFS or SPL estimate
├─ Auto-reduce threshold - Room-level gain reduction trigger
├─ Audio/video export defaults
└─ Output naming conventions

Most settings are discovered automatically. Adjust only if your local setup differs.

 TROUBLESHOOTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

- If the app fails to launch from source, re-check the Python environment and installed requirements.
- If the packaged build will not start, verify the entire `build_system\dist\KaraokeStudioPro\` folder is present and run the app from that folder.
- If you are reporting an issue, include the files from the project `logs\` folder and note whether the issue occurs in source mode or packaged mode.
- For packaging and bundling details, see `build_system\BUILD_GUIDE.md` and `documentation\LOGGING.md`.

 BUNDLED COMPONENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This package includes all required runtime components:

✓ FFmpeg               - Video encoding/transcoding engine
✓ FFprobe              - Media metadata/duration analysis engine
✓ yt-dlp               - YouTube content downloader
✓ VLC Libraries        - Media playback engine (libvlc.dll + plugins)
✓ PySide6              - Qt6 GUI framework
✓ Python libraries     - numpy, sounddevice, and related runtime support

No additional installations are normally required for the bundled app.
The Demucs separator is fully supported in packaged builds when the offline model cache is present.
